# 01 · 需求规格

> 本文定义「幕间」要解决的问题、给谁用、做到什么程度算完成。技术实现见 [02 系统架构](02-architecture.md)，场景机制的细节见 [04 场景插入设计](04-scene-injection.md)。

## 1. 需求来源

来自用户原话（2026-11-10）：

> 帮我创建一个新项目，我想做一个类似于酒馆的场景对话式 AI，可以自定义接入模型，用来角色扮演，我可以在对话的时候，在不同的地方输入类似于场景来描述要求等等。你帮我设计一下整体的架构和用户的需求，等我都确认完以后再开发

拆解与对应关系：

| 原话 | 我们的理解 | 对应需求 |
| --- | --- | --- |
| 「类似于酒馆」 | 以 SillyTavern 为体验基线：角色卡、人设、世界书、提示词管理、分支重写，但不必复刻它的全部复杂度 | FR-CHAR、FR-PERS、FR-PROMPT、FR-CHAT、FR-WI |
| 「可以自定义接入模型」 | 任意 OpenAI 兼容端点即可接入：官方 API、中转站、本地 Ollama / LM Studio、自建服务；密钥只留在本地 | FR-MDL |
| 「用来角色扮演」 | 角色一致性、沉浸感、长对话可用，而不是通用聊天助手 | FR-CHAR、FR-CHAT、NFR-03 |
| 「在对话的时候，在不同的地方输入类似于场景来描述要求」 | 「场景」不是只会出现在开头的设定，而是可以在**上下文的任意位置**、**对话时间线的任意节点**、以**不同身份**注入的导演指令，且能选择只生效一轮或持续生效 | FR-SCENE、[04 场景插入设计](04-scene-injection.md) |
| 「等我都确认完以后再开发」 | 本阶段只交付设计与决策清单；确认后才写代码 | [05 路线图](05-roadmap-decisions.md) |

## 2. 目标与非目标

### 2.1 产品目标

1. **让「改戏」像聊天一样自然**：任何时候都能插入场景、要求、状态变更，模型下一轮就按新设定演，不需要重开对话或改角色卡。
2. **模型自由**：不为模型厂商做嫁衣。用户有自己的 API / 中转 / 本地模型，就能用；换模型不改使用习惯。
3. **酒馆用户零迁移成本**：角色卡能直接导入，核心概念（深度、世界书、预设）对得上。
4. **数据留在自己机器上**：默认本地运行，会话、角色、密钥都不经过第三方服务器（模型请求本身除外）。

### 2.2 非目标（本版本不做）

- 不做通用 AI 助手 / 生产力工具，只服务角色扮演与互动叙事。
- 不做模型训练、微调、RAG 知识库平台。
- 不做角色卡 / 场景的社区分享市场（P2 之后再议）。
- 不做多人实时同房跑团（群聊 P2，多用户 P2）。
- 不内置任何模型额度或代理服务，用户自带 Key。

## 3. 目标用户与典型场景

### 3.1 用户画像

| 画像 | 特征 | 最在意 |
| --- | --- | --- |
| **写手 / 语C 玩家**（主要） | 有固定角色和世界观，习惯用角色卡，追求角色口吻稳定、剧情可推进 | 角色一致性、场景可控、能导入已有角色卡 |
| **技术型玩家** | 用 DeepSeek / 中转站 / 本地 Ollama，关心成本、延迟、隐私 | 接入简单、密钥安全、能看请求调试 |
| **互动小说 / 跑团爱好者** | 边聊边改设定，喜欢分支和「如果当时……」 | 时间线场景、分支回溯、导出存档 |

### 3.2 典型旅程

**旅程 A：第一次使用（目标 3 分钟内开始聊天）**

1. 打开本地页面 → 引导页选择「配置模型」。
2. 选择预设「DeepSeek」→ 粘贴 Key → 点「测试连接」通过 → 选择模型。
3. 导入一张 SillyTavern PNG 角色卡 → 自动带出头像、开场白、示例对话。
4. 点「开始聊天」→ 看到开场白 → 输入第一句 → 流式收到回复。

**旅程 B：中途改戏（核心场景）**

1. 已聊到第 30 条，剧情在咖啡馆。
2. 在某条消息的菜单里点「在此之后插入场景」→ 填「深夜，暴雨，突然停电，角色手机响起」→ 选「插入剧情」（默认持续生效）。
3. 时间线上出现一张场景卡片，位置就在那条消息之后。
4. 发下一句 → 模型按新场景继续演；场景卡片可随时展开编辑或停用。

**旅程 C：一次性导演指令**

1. 希望「这一轮让角色主动道歉，但嘴硬」。
2. 点输入框上方的「＋场景」→ 选「这一轮要求」→ 填要求。
3. 发送后，该场景只进入这一次请求；回复完成后自动标记为「已用」并停用。

**旅程 D：换模型对比**

1. 同一个会话里把模型从 DeepSeek 切到本地 Qwen。
2. 上下文、角色、场景完全不变，只换 provider / 参数；重新生成最后一条即可对比。

## 4. 产品原则

1. **本地优先**：默认单用户、本地运行；能离线（接本地模型时）使用。
2. **场景是一等公民**：场景不是「作者注记」的附属功能，有自己的数据结构、位置语义、UI 和预览。
3. **渐进式复杂度**：新手只需「选模型 → 选角色 → 聊天」；深度、世界书、预设顺序等高级能力收在抽屉里。
4. **透明可解释**：模型看到了什么，用户就能看到什么（上下文预览 / token 预算 / 错误原因）。
5. **兼容而不绑定**：角色卡、世界书尽量兼容酒馆格式；数据可完整导出，不锁定。
6. **新手默认可用**：内置推荐参数与三种场景意图，先能用再调优；深度、身份、排序、token 细节默认不出现。
7. **用现成组件**：界面基于 Ant Design 等成熟组件库，自研只限聊天消息流、场景卡片等领域组件。

### 4.1 新手优先的交互

目标：新用户不需要理解「深度」「身份」「排序」「token」这些词，也能在 3 步内插入场景并看到效果；需要精细控制时再展开。

**内置默认参数（可在设置中改，不需要新手理解）**

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 模型参数 | temperature 0.8 / top_p 0.95 / max_tokens 1024 | 角色扮演的通用起点 |
| 上下文窗口 | 按 provider 预置；未知时 8192 | 可在 provider 高级设置里改 |
| 历史 | 预算内尽量多带，至少最近 2 轮 | 超限自动裁剪并提示 |
| 提示词 | 内置「标准角色扮演」预设 | 主提示词可改，可恢复推荐 |
| 场景身份 | system | 高级选项可改 |
| 界面模式 | 简单模式、跟随系统主题 | 高级模式在设置里切换 |
| 新手引导 | 3 步：选模型 → 选 / 导入角色 → 开始聊天 | 可跳过，默认参数自动生效 |

**三种场景意图（简单模式只显示这三个）**

| 意图 | 用户看到的话 | 内部映射 | 默认时长 |
| --- | --- | --- | --- |
| 当前场景 | 现在在哪、气氛如何、有什么规则 | `system-top` | 持续 |
| 插入剧情 | 在这条消息之后发生一件事 | `anchored`（锚定当前消息） | 持续 |
| 这一轮要求 | 只影响下一轮回复 | `depth: 0` | 仅下一轮 |

- 打开方式：输入框「＋场景」默认「这一轮要求」；消息菜单「在此之后插入剧情」默认「插入剧情」；场景面板默认「当前场景」。
- 「高级选项」折叠深度、身份、排序、token 细节；展开后与 [04](04-scene-injection.md) 的完整模型一致。
- 简单模式下场景卡片只显示标题 + 意图 + 内容摘要；技术位置放在高级详情里。

**对话框默认分段输入（对话为主，补充项按需展开）**

| 字段 | 用户输入 | 说明 |
| --- | --- | --- |
| 场景 | 时间、地点、天气、氛围 | 可选；标为「导演注记」，随这条消息发送，M3 可升级为场景卡片 |
| 动作 | 你做了什么 | 可选 |
| 神态 / 心理 | 神情、语气、心里的想法 | 可选；比单纯「表情」更适合角色扮演 |
| 对话 | 你说出口的话 | 主输入；只有对话时按普通文本发送 |

- 默认只显示「对话」和三个补充按钮；点击「场景 / 动作 / 神态」才展开对应输入，避免一上来就是四个大框。
- 至少一项非空；多段时组合为一条 user 消息，并用【场景】【动作】【神态】【对话】标记。
- 底部提供「预览」，可看到组合后的完整消息；可切换「自由输入」，切换时保留已输入内容。
- 补充字段 Enter 跳到对话；对话 Enter 换行；Ctrl / ⌘ + Enter 发送。

**交互逻辑约束**

- 不确定发什么时，点输入区「帮我想想」：AI 根据角色与最近对话给出 3 条建议，点击填入，不自动发送。
- 每个界面只有一个主操作（发送 / 保存 / 开始聊天），次要操作收进菜单。
- 任何一步都能返回或取消；破坏性操作有确认，场景停用可随时恢复。
- 错误用「发生了什么 + 怎么解决」的人话，不直接抛错误码。
- 首次进入显示空状态引导；不强制配置所有参数，未设置的用默认值。

**新手主路径（全程不展开高级选项）**：打开页面 → 选「快速开始」→ 选模型预设并填 Key → 导入 / 选择一个角色 → 开始聊天 → 输入框「＋场景」→ 选「这一轮要求」并填内容 → 发送。

**核心验收场景（Given / When / Then）**

- **场景插入**：给定会话已有 10 条消息，当用户在第 5 条后插入「停电」场景并发送下一条消息，则最终请求中该场景出现在第 5 条消息之后，且预览能显示插入点与 token 数。
- **一次性**：给定一个「仅下一轮」场景，当生成成功完成后，则该场景自动停用；重新生成上一轮时**不会**再次注入（除非手动启用）。
- **深度语义**：给定历史长度 4，depth=0 的场景位于最后一条消息之后；depth=1 位于最后一条消息之前；depth=4 位于第一条消息之前；depth=99 收敛为第一条之前并给出提示。
- **裁剪**：给定上下文超预算，系统优先保留系统提示、启用的场景、最近消息；被裁剪的历史在预览中标记，且不会出现孤儿场景导致的请求失败。

## 6. 非功能需求

| ID | 类别 | 要求 |
| --- | --- | --- |
| NFR-01 | 隐私 | 默认本地运行；不上报遥测；会话 / 角色 / 密钥不出本机；仅把必要上下文发给用户配置的模型端点 |
| NFR-02 | 安全 | 密钥 AES-256-GCM 加密存储；日志脱敏；模型输出按不可信内容渲染（禁用原始 HTML）；导出默认不含密钥 |
| NFR-03 | 性能 | 1 万条消息的会话可流畅滚动（虚拟列表）；上下文装配 < 50ms（不含网络）；首 token 取决于模型，UI 不额外阻塞 |
| NFR-04 | 兼容 | Chrome / Edge / Safari 最近两个大版本；桌面优先，移动端可聊天；SQLite 单文件可迁移 |
| NFR-05 | 可靠性 | 生成中断可恢复（保留部分内容）；数据库自动备份；升级有迁移；异常不丢历史 |
| NFR-06 | 可维护性 | 模型适配器、提示词片段、场景类型可扩展；核心装配逻辑纯函数、可快照测试 |
| NFR-07 | 可用性 | 中文界面；空状态有引导；破坏性操作有确认；键盘可达 |
| NFR-08 | 可观测性 | 本地结构化日志；请求 ID；可选调试面板显示最近一次请求 / 响应（脱敏） |
| NFR-09 | 部署 | 开发一条命令；生产可单进程或 Docker；数据卷挂载；端口可配置 |
| NFR-10 | 合规 | 角色卡 / 世界书导入尊重原作者标注；导出保留 creator notes；不内置侵权素材 |

## 7. 范围与版本

### 7.1 P0（MVP）

模型接入（OpenAI 兼容）、角色与人设、角色卡 V2 导入、基础对话与分支重写、场景插入（三种位置 × 两种时长）、上下文预览、基础提示词与宏、新手模式与默认参数、对话框分段输入（场景 / 动作 / 神态 / 对话）、AI 推荐下一条、会话导出导入、本地存储与主题。

### 7.2 P1（增强）

世界书、提示词预设高级编辑、原生 Anthropic / Gemini、Ollama 自动发现、场景模板、场景状态栏、长对话摘要记忆、正则后处理、角色卡 PNG 导出、搜索、备份、Docker、快捷键、英文界面。

### 7.3 P2（远期）

群聊 / 多角色同场、场景库共享、图像生成、TTS / 语音输入、插件系统、多用户与云同步、桌面 / 移动客户端。

### 7.4 明确不做

模型训练与微调、通用助手能力（联网搜索、代码执行）、社区内容审核平台、付费订阅与额度代理、角色卡市场。

## 8. 成功度量

| 指标 | 目标 |
| --- | --- |
| 首次使用到发出第一条消息 | ≤ 3 分钟（含配置模型） |
| 插入一个场景的操作步数 | ≤ 3 步（不含输入内容），且新手无需理解「深度」等概念 |
| 场景插入后模型遵循率 | 主观抽测 ≥ 80%（受模型能力影响，用模板与位置优化） |
| 长对话（> 200 条）可用性 | 不因超上下文直接失败；有裁剪与提示 |
| 数据可迁移 | 任意会话可导出并在另一台机器导入还原 |
| 崩溃 / 异常丢数据 | 0（已发送消息与已生成内容均持久化） |
