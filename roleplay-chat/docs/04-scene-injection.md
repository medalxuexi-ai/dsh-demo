# 04 · 场景插入设计

> 这是「幕间」区别于普通酒馆前端的核心机制。目标：用户可以在**对话时间线的任意节点**、**上下文的任意位置**、以**合适的身份**插入一段「场景 / 导演指令」，并且清楚地知道它会在什么时候、以什么形式进入模型上下文。

## 1. 心智模型

把一次对话想象成一场戏：

- **角色卡** = 演员是谁、性格如何；
- **人设** = 你演谁；
- **历史消息** = 已经演过的戏；
- **场景** = 导演在剧本边上写的舞台说明：此刻是雨夜、灯灭了、镜头推近、这一条要欲言又止。

舞台说明**不是台词**。角色不应该把「深夜，暴雨」念出来，而应该在该设定下反应。因此场景需要：

1. 与普通消息分开存储和渲染（不污染对话气泡）；
2. 有明确的注入位置（系统层 / 深度 / 时间线锚点）；
3. 有明确的生效时长（持续 / 仅下一轮）；
4. 可与角色卡、世界书共存，而不是互相覆盖。

## 2. 三个正交维度

| 维度 | 取值 | 回答的问题 |
| --- | --- | --- |
| **位置** `placement` | `system-top` / `depth` / `anchored` | 放进上下文的哪里？ |
| **时长** `lifetime` | `persistent` / `once` | 从什么时候生效到什么时候？ |
| **身份** `role` | `system` / `user` / `assistant` | 以谁的口吻进入上下文？ |

> 早期草稿里出现过第四种位置 `chat-end`，实现前收敛掉：它与 `depth: 0` 的落点重叠，保留会让语义和 UI 都变复杂。需要「贴近模型下一轮」的指令统一用 `depth: 0`。

### 2.1 三种位置

**① 系统常驻 `system-top`**

- 落点：系统提示词块内，角色定义 / 人设之后（预设顺序 `order = 50`）。
- 适合：世界观补充、叙事风格、全局规则、当前大场景状态。
- 特点：永远在，和最近说了什么无关；不随历史滚动消失。
- 示例：「叙事用第二人称，克制、留白；不要替用户决定行动。」

**② 深度插入 `depth`**

- 落点：从当前分支末尾往前数第 `depth` 条**消息**之前；`0` 表示最后一条消息之后（即生成回复前紧邻）。
- 适合：作者注记式的短期提醒、当前气氛、下一轮的具体要求。
- 特点：位置相对「对话末尾」滑动，永远靠近模型当前要回应的位置。
- 示例：`depth: 0` + 仅下一轮 →「这一轮让角色主动提出离开，但语气犹豫。」

**③ 时间线锚定 `anchored`**

- 落点：某条具体消息之后；场景在对话流里以卡片形式出现在该消息下面。
- 适合：剧情事件、转折、一次性的舞台变化（「就在这时，停电了」）。
- 特点：位置固定，不随新消息滑动；锚点消息被删除或不在当前分支时失效；随历史滚动出窗口后自然淡出。
- 示例：在第 12 条消息后插入「深夜，暴雨，咖啡馆突然断电」。

### 2.2 两种时长

| 时长 | 行为 | 典型用法 |
| --- | --- | --- |
| `persistent` | 启用期间每一轮都注入；用户手动关闭才停止 | 当前场景状态、长期叙事规则 |
| `once` | 只注入下一次生成；成功完成后自动停用并标记「已用」 | 单轮导演要求、剧情突转 |

规则细节：

- `once` 在**生成成功结束**（`stop` / `length`）后消费；失败、取消、连接中断**不消费**，重试仍生效。
- `once` 被消费后再点「重写」不会再次注入；需要重用时手动重新启用。
- `once` 的停用不删除内容，列表里显示「已用」，可一键再次启用。
- `persistent` 场景若锚点消息被裁出上下文窗口，**不再注入**并给出 warning（见 §5.3）。需要长期存在的设定请用 `system-top` 或 `depth`。

### 2.3 身份

| 身份 | 适用 | 注意 |
| --- | --- | --- |
| `system`（默认） | 绝大多数场景 | 最像「舞台说明」；部分模型对历史中间的 system 支持差，由适配器降级 |
| `user` | 需要以「旁白 / 场记」口吻表达、或模型只接受 user 前缀时 | 可能被模型当成用户发言回应，需配包装模板 |
| `assistant` | 希望预演一段旁白、把叙事权交给模型续写（近似 prefill） | 会看起来像角色已经说了一段，慎用 |

默认使用 `system`，并在包装模板里明确「这不是台词」。身份是高级选项，收在场景编辑器第二行。

### 2.4 三种意图（新手默认入口）

简单模式不展示 `placement` / `depth` / `role`，只问「你想做什么」：

| 意图 | 用户语言 | 内部映射 | 默认时长 | 从哪里进入 |
| --- | --- | --- | --- | --- |
| **当前场景** | 现在在哪、气氛如何、有什么规则 | `system-top` | 持续 | 场景面板、输入框「＋场景」 |
| **插入剧情** | 在这条消息之后发生一件事 | `anchored`（锚定选中的消息） | 持续 | 消息菜单、输入框「＋场景」 |
| **这一轮要求** | 只影响下一轮回复 | `depth: 0` | 仅下一轮 | 输入框「＋场景」（默认） |

- 意图是 UI 概念，由 `placement` + `lifetime` 推导，不额外落库；系统常驻 → 当前场景，锚定 → 插入剧情，`depth:0` + `once` → 这一轮要求，其余显示为「高级场景」。
- 高级选项展开后仍可改位置 / 身份 / 排序；简单模式只是默认值与表单布局，不是另一套数据。
- 从消息菜单进入时预填锚点；从场景面板进入时默认「当前场景」；从输入框进入时默认「这一轮要求」，选「插入剧情」时默认锚定最后一条消息。

## 3. 深度语义（必须精确）

设当前分支的历史为 `[m1, m2, …, mN]`（N 为最后一条，通常是用户刚发的消息）：

| depth | 插入位置 |
| --- | --- |
| `0` | `mN` 之后（生成回复之前，最靠近模型的一轮） |
| `1` | `mN` 之前 |
| `2` | `m(N-1)` 之前 |
| `k` | `m(N-k+1)` 之前（`1 ≤ k ≤ N`） |
| `> N` | 收敛为 `m1` 之前，并产生 warning |

```text
            depth=4   depth=3   depth=2   depth=1   depth=0
               │         │         │         │         │
  [m1]       [m2]      [m3]      [m4]      [m5]  ──▶ 生成回复
```

要点：

- 深度按**消息**计数，不把场景卡片算进去；否则插入场景会改变其他场景的深度，导致不可预测。
- 深度相对**当前分支的叶节点**计算，不是整个会话。切分支后深度位置随之变化，这是预期行为。
- 同一点位有多个片段时：锚定场景在前，深度场景在后；同类按 `sortOrder` 升序、再按创建时间。
  - 因此 `depth: 0` 的场景总是紧贴「生成回复」之前，位置最靠近模型。

## 4. 数据结构

```ts
type SceneRole = 'system' | 'user' | 'assistant';

type ScenePlacement =
  | { mode: 'system-top' }
  | { mode: 'depth'; depth: number }              // 0 = 最后一条消息之后
  | { mode: 'anchored'; messageId: string };      // 锚定消息之后

type SceneLifetime = 'persistent' | 'once';

interface SceneDirective {
  id: string;
  chatId: string;
  title: string;              // 可空，空时用内容前 20 字
  content: string;            // 支持宏
  role: SceneRole;            // 默认 system
  placement: ScenePlacement;  // 默认 { mode: 'depth', depth: 0 }
  lifetime: SceneLifetime;    // 默认 persistent
  enabled: boolean;
  sortOrder: number;          // 同位置排序
  consumedAt: string | null;  // once 被消费的时间
  createdAt: string;
  updatedAt: string;
}
```

**派生字段（API 返回，不落库）**

```ts
interface SceneView extends SceneDirective {
  placementValid: boolean;    // 锚点是否存在于当前分支
  placementLabel: string;     // 「系统常驻」「深度 0」「第 12 条之后」
  previewTokens: number;      // 含包装模板的估算
}
```

**包装模板（默认，可配置）**

```text
【场景说明｜导演指令】
以下是舞台说明，不是角色台词。请在这个设定下继续叙事，不要直接复述本段内容。
{title ? "标题：" + title : ""}
{content}
```

- 包装模板在 token 估算之前拼上，所以预览显示的是真实占用。
- `role: user` 时默认改用 `[场景说明] …` 前缀；`role: assistant` 时原样输出（由用户自行控制）。
- 高级设置里可关闭包装（不推荐），或自定义模板（P1）。

## 5. 上下文装配

### 5.1 场景进入装配的顺序

```text
1. 读取当前分支历史与所有启用场景
2. 过滤：停用 / 已消费的 once / 锚点无效
3. 宏展开 + 套包装模板
4. 分配插入点：
   system-top → 系统块（预设 order = 50）
   anchored   → 锚点消息之后
   depth      → 从末尾数第 depth 条消息之前（depth 0 在最后一条之后）
5. 处理同点排序（锚定 → 深度 → sortOrder）
6. 计入 token 预算，裁剪历史，产出 trace
```

### 5.2 与历史、末尾指令的相对顺序

最终消息数组（示意）：

```text
[system] 主提示词
[system] 角色系统提示词
[system] 角色定义
[system] 人设
[system] 系统常驻场景（可多条，按 sortOrder）
[user]   m1
[assistant] m2
[system] 锚定在 m2 之后的场景
[user]   m3
…
[user]   mN
[system] depth 0 场景（紧贴生成前）
[system] 末尾指令（预设 post-history）
（P1）[assistant] prefill
```

- `depth 0` 场景在最后一条消息之后、末尾指令之前；两者都是「生成前最后看到的内容」。
- 若 provider 不支持历史中的 system，适配器把对应场景转成 `user` 消息并加 `[场景说明]` 标记，预览里显示**实际角色**。

### 5.3 裁剪与失效

| 情况 | 行为 |
| --- | --- |
| 固定开销（系统提示 + 角色 + 人设 + 系统常驻场景）已超预算 | **不发送**，返回 `CONTEXT_LENGTH_EXCEEDED`，提示关闭场景 / 缩短提示词 / 降低输出上限 |
| 历史超预算 | 从最旧的消息开始裁剪；至少保留最近 2 轮与最后一条用户消息 |
| 锚定场景的锚点消息被裁掉 | 该场景本轮不注入；trace 标记 `TRIMMED_ANCHOR`；UI 在场景列表提示「已超出上下文窗口」 |
| 锚点消息被删除 | 场景保留但 `placementValid=false`，不注入；提示重新锚定（`ORPHANED_ANCHOR`） |
| 锚点消息在别的分支 | 同样不注入；提示「当前分支不可见」，P2 再做分支级场景 |
| 深度大于历史长度 | 收敛到最早一条之前，warning `DEPTH_CLAMPED` |
| `once` 场景因锚点失效未注入 | 不消费，保持启用，修好锚点后仍可用 |
| 场景内容为空 | 创建 / 更新时校验失败 |

**为什么锚定场景被裁掉不「提升到窗口起点」？**

因为锚定语义就是「在那个时间点发生的事」。把它挪到窗口开头会制造一个从未发生过的场景，误导模型。需要跨窗口持久的设定，应该用 `system-top` 或 `depth`。这是有意的产品选择，会在 UI 上解释清楚。

### 5.4 伪代码

```ts
function insertScenes(history: Message[], scenes: SceneDirective[]) {
  const out: PromptItem[] = [];
  const anchoredByMessage = groupBy(
    scenes.filter(s => s.placement.mode === 'anchored'),
    s => s.placement.messageId,
  );
  const depthScenes = scenes.filter(s => s.placement.mode === 'depth');
  const n = history.length;

  for (let i = 0; i < n; i++) {
    // depth ≥ 1：插在第 i 条消息之前，depth = n - i
    const insertBefore = depthScenes.filter(
      s => s.placement.depth === n - i && s.placement.depth > 0,
    );
    for (const s of sortScenes(insertBefore)) out.push(toPromptItem(s));

    out.push(history[i]);

    // 锚定场景：紧跟在锚点消息之后（先于该消息的后续子消息）
    for (const s of sortScenes(anchoredByMessage.get(history[i].id) ?? [])) {
      out.push(toPromptItem(s));
    }
  }

  // depth 0：最后一条消息之后、生成之前；排在最后一条消息的锚定场景之后
  for (const s of sortScenes(depthScenes.filter(s => s.placement.depth === 0))) {
    out.push(toPromptItem(s));
  }

  // system-top 场景单独进入 system 块，不在此函数内
  return out;
}
```

> 上面是语义示意，实际实现会先做宏展开、包装、token 估算，并产出 trace。

### 5.5 一次性消费

```text
生成开始 → 记录本轮使用的 once 场景集合
生成成功结束 → 对这些场景设置 enabled=false、consumedAt=now
生成失败 / 取消 / 断开 → 不做任何消费
```

- 消费在事务中完成，和助手消息落库同一事务，避免「消息存了但场景没消费」或反过来。
- 重写 / 重新生成时按当时启用状态重新计算，不复用上一轮快照。

## 6. 交互设计

### 6.1 聊天页

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 幕间            林晚 ▾   雨夜咖啡馆 ▾                    [上下文] [⚙] │
├──────────────┬───────────────────────────────────────┬───────────────┤
│ 角色          │                                       │ 场景           │
│ ▸ 林晚        │   ┌─────────────────────────────┐     │ ┌───────────┐ │

│ 会话          │   ┌─────────────────────────────┐     │ ├───────────┤ │

│              │   └─────────────────────────────┘     │               │
└──────────────┴───────────────────────────────────────┴───────────────┘
```

- **时间线场景卡片**：只显示 `anchored` 场景。虚线边框、导演板图标，与消息气泡区分；点击展开全文与操作（编辑 / 停用 / 删除 / 复制 / 改锚点）。
- **常驻场景栏**：输入框上方一行 chip，显示启用中的 `system-top` / `depth` 场景；点击定位到编辑，`×` 直接停用。
- **场景面板（右抽屉）**：所有场景列表；简单模式显示意图、启用状态与内容摘要，高级模式再显示位置 / 时长 / token；支持筛选「启用中 / 全部 / 已用」。
- **消息菜单**：「在此之后插入场景」→ 打开编辑器并预填锚点；「重写」「编辑」「删除」「复制」并列。锚定场景位于该消息与其后续消息之间；若只想影响**下一轮回复**，用输入框的「＋场景」（默认「这一轮要求」）更直接。
- **输入框**：默认「分段输入」（见 §6.4）；`＋场景` 按钮、`/scene` 命令用于导演场景（M3）；`/ooc` 可选（把一段括号内容作为一次性 user 场景，P1）。
- **上下文预览**：顶部按钮打开抽屉，按最终顺序列出片段、来源、角色、token、裁剪原因；支持复制 JSON（Key 脱敏）。

### 6.2 场景编辑器

```text
┌─ 新建场景 ──────────────────────────────────────────────┐
│ 你想做什么？                                             │
│ ● 当前场景    现在在哪、气氛如何、有什么规则             │
│ ○ 插入剧情    在这条消息之后发生一件事                   │
│ ○ 这一轮要求  只影响下一轮回复                           │
│                                                         │
│ 内容   [ 深夜，暴雨。咖啡馆突然断电，只有应急灯亮着。]    │
│        [ 角色的手机在口袋里震动。                    ]    │
│ 标题   [ 雨夜停电（可选）                          ]     │
│                                                         │
│ 预计占用  42 tokens           [高级选项 ▾]              │
│                                   [取消]  [保存并插入]   │
├─ 高级选项（默认折叠）───────────────────────────────────┤
│ 位置  [ 系统常驻 / 第 12 条之后 / 深度 0 ]               │
│ 身份  [ system ▾ ]        排序 [ 0 ]                     │
│ 生效  [ 持续 / 仅下一轮 ]                                │
│ ⓘ 深度 0 = 最后一条消息之后；一般不需要改这些             │
└─────────────────────────────────────────────────────────┘
```

交互细节：

- **默认简单模式**：只显示三个意图 + 内容 + 可选标题 + token 估算；深度、身份、排序、锚点细节收进「高级选项」。
- 打开编辑器时按入口预选意图（见 §2.4）；从消息菜单进入时预填锚点。
- 保存后立即出现在时间线或常驻栏，但**不重新生成**；下一次请求生效。
- 编辑 / 停用即时生效于下一轮；已经生成的消息不受影响。
- 场景卡片在简单模式下显示意图徽标与内容摘要；技术位置放在高级详情里。
- 复制场景默认**停用**，避免重复注入。
- 删除需确认；`once` 已用场景可一键「再次启用」。
- 切到高级模式只改展示，不改已有场景数据。

```text
│ [system] 主提示词                              412      │
│ [system] 角色定义 · 林晚                       286      │
│ [system] 场景 · 叙事风格（系统常驻）             58      │
│ [user]   你推开门，风铃响了一声。                18      │
│ [asst]   林晚抬起头……                          96      │
│ [system] 场景 · 雨夜停电（第 12 条之后）         42      │
│ …                                                       │
│ ⚠ 已省略最早 6 条消息（TRIMMED_HISTORY）                │
│ [复制 JSON]                                   [关闭]    │
└─────────────────────────────────────────────────────────┘
```

简单模式先给一句人话摘要：「这条场景会在第 12 条之后生效，持续到关闭」，需要时再展开完整列表。预览是「场景插入」可信度的关键：用户不需要猜模型到底看没看到。

### 6.4 对话框分段输入（消息级，M1 已实现）

> 这是「用户这一条消息」的输入结构，**不是**上文可定位的导演场景卡片。场景字段随这条消息一起发送；M3 可以增加「提升为场景卡片」，把同一段内容变成可定位、可持久化的场景。

**默认形态（对话为主，补充项按需展开）**

```text
┌─ 对话输入 ──────────────────────────────────────────────┐
│ [分段输入] [自由输入]        [＋场景] [＋动作] [＋神态]   │
│                                                         │
│ 对话                                                    │
│ [ 我来晚了。                                            ]│
│                                                         │
│ [预览] 1 段 · 6 字 · Ctrl/⌘+Enter              [发送]   │
└─────────────────────────────────────────────────────────┘
```

**展开补充项后**

```text
┌─ 对话输入 ──────────────────────────────────────────────┐
│ [分段输入] [自由输入]        [场景] [动作] [神态]         │
│ ┌ 本轮场景  [导演注记]                              × ┐ │
│ │ 雨夜，旧城咖啡馆，窗外在下雨。                      │ │
│ └────────────────────────────────────────────────────┘ │
│ ┌ 动作                                         × ┐     │
│ │ 推开门，抖了抖伞上的水。                        │     │
│ └────────────────────────────────────────────────┘     │
│ ┌ 神态 / 心理                                  × ┐     │
│ │ 有点心虚，视线避开吧台。                        │     │
│ └────────────────────────────────────────────────┘     │
│ 对话                                                    │
│ [ 我来晚了。                                            ]│
│ [预览] 4 段 · 42 字 · Ctrl/⌘+Enter              [发送]   │
└─────────────────────────────────────────────────────────┘
```

**字段决策（按系统能力收敛，而不是照搬示例）**

| 字段 | 保留原因 | 交互 |
| --- | --- | --- |
| 对话 | 角色扮演的核心输出；只有它时保持自然对白 | 默认展开，主输入 |
| 动作 | 用户的行为，模型需要知道「你做了什么」 | 点击「动作」展开；可空 |
| 神态 / 心理 | 比单纯「表情」更完整：神情、语气、内心活动 | 点击「神态」展开；可空 |
| 场景 | 系统的一等功能；但完整的场景卡片在 M3，这里先提供「本轮导演注记」 | 点击「场景」展开；带「导演注记」标签 |

**没有新增的字段**

- 不新增「旁白 / 系统指令」：它们与角色卡、人设、场景的职责重叠，容易让用户不知道写在哪。
- 不把「表情」单独保留：表情是神态的一部分，合并为「神态 / 心理」更贴角色扮演。
- 不默认铺开四个输入框：新手打开时只有一个对话框 + 三个补充按钮，减少认知负担。

**规则**

- 至少一项非空；只有「对话」时按普通文本发送，多段时按【场景】【动作】【神态】【对话】顺序组合成一条 user 消息。
- 底部「预览」可看到组合后的完整文本；`n 段 · m 字` 提示将发送多少内容。
- 补充字段 Enter 跳到对话；对话 Enter 换行；Ctrl / ⌘ + Enter 在任意字段发送。
- 保留「自由输入」单框模式；切换模式时保留已输入内容。
- 场景字段是**消息级上下文**，不是导演场景；M3 的「提升为场景卡片」会复用同一段文本，避免用户重复输入。

## 7. 典型用法与最终上下文

### 7.1 全局叙事风格（system-top + persistent）

场景：「第二人称叙事，短句，留白；不要替用户决定行动。」

最终上下文：

```text
system: 主提示词
system: 角色定义（林晚……）
system: 「第二人称叙事，短句……」
user:   你推开门……
assistant: 林晚抬起头……
```

### 7.2 剧情转折（anchored + persistent）

在第 12 条消息后插入「深夜，暴雨，突然断电」。

```text
… (m10, m11, m12)
system: 【场景说明】深夜，暴雨，突然断电……
user:   你摸黑向前走了两步。
assistant: （模型基于断电场景回复）
```

该场景会一直在 m12 之后，直到历史窗口把它裁掉；用户也可以手动停用（表示「电来了」）。

### 7.3 单轮导演（depth 0 + once）

历史末尾是用户消息 mN。插入「这一轮让林晚主动道歉，但嘴硬、不肯直说」。

```text
… [user] mN
[system] 【场景说明】这一轮让林晚主动道歉……
（模型回复；成功后场景自动停用）
```

### 7.4 组合：长期设定 + 当前事件 + 单轮要求

```text
[system] 叙事风格：克制、留白（system-top，持续）
[user] mN
[system] 当前场景：凌晨两点，雨停了（depth 0，持续）
[system] 这一轮：让角色沉默三秒再开口（depth 0，一次性）
```

同一位置按 `sortOrder` 排序，`once` 场景在最后，最靠近模型。

## 8. 与其他设定来源的关系

| 来源 | 默认位置 | 生效方式 | 与场景的关系 |
| --- | --- | --- | --- |
| 角色卡 `scenario` | 角色定义（system-top） | 每轮 | 角色自带的初始背景；场景是更高层的导演覆盖，位置更靠后 |
| 世界书（P1） | 按条目配置 | 关键词命中 | 提供事实；场景提供导演意图；可同时存在 |
| 预设末尾指令 | chat-end | 每轮 | 全局格式 / 安全提示；depth 0 场景在其之前 |
| 作者注记（酒馆概念） | depth | 每轮 | 本项目统一用 `depth` 场景表达；导入预设时映射 |
| 用户消息里的 OOC | 时间线自然位置 | 随历史 | 一次性、会进入历史；场景可停用、可定位、可预览，更适合反复修改 |
| 普通消息 | 时间线 | 永久 | 场景不是消息，不参与角色交替、不进消息树、不显示为气泡 |

## 9. 边界与规则清单

| # | 情况 | 规则 |
| --- | --- | --- |
| 1 | 同一位置多个场景 | 锚定先、深度后；同类按 `sortOrder` → `createdAt` |
| 2 | 场景停用 | 不注入，保留在列表与时间线（灰色） |
| 3 | `once` 生成失败 | 不消费，保持启用 |
| 4 | `once` 已消费后重写 | 不注入；手动重新启用才生效 |
| 5 | 锚点消息删除 | 场景保留但失效，提示重新锚定 |
| 6 | 锚点消息被裁剪 | 本轮不注入，warning |
| 7 | 锚点在其他分支 | 不注入，提示「当前分支不可见」 |
| 8 | depth > 历史长度 | 收敛到最早消息之前 + warning |
| 9 | 系统常驻场景过多导致超预算 | 阻止发送，明确指出哪些场景需关闭 |
| 10 | 模型不支持历史中的 system | 适配器降级为 user + 标记，预览显示实际角色 |
| 11 | 场景含未知宏 | 保留原文 + warning |
| 12 | 场景为空 | 校验失败 |
| 13 | 复制场景 | 默认停用 |
| 14 | 删除会话 | 场景级联删除 |
| 15 | 导出 / 导入 | 场景随会话导出；锚点按消息 id 重建，找不到则标记失效 |
| 16 | 生成中编辑场景 | 只影响下一次请求 |
| 17 | 切换分支 | 只注入当前分支可见的锚定场景 |
| 18 | 多个 `depth: 0` 一次性场景 | 全部注入；按 sortOrder 排列；成功后全部消费 |

## 10. 不做与后续

**P0 不做**

- 场景自动生成（让模型根据剧情建议下一场景）——想法很好，但会引入额外模型调用与不可控成本，P2 再议。
- 场景状态机 / 变量系统（时间、地点、人物关系的结构化状态）——P1 先做轻量「场景状态栏」。
- 场景库 / 社区共享。
- 分支级场景（场景只属于某条分支）。
- 拖拽调整场景顺序（P0 用数字 / 上移下移按钮）。

**P1 候选**

- 场景模板（环境、镜头、时间推进、单轮导演）。
- 场景状态栏：时间 / 地点 / 在场人物，一键编译为 `system-top` 场景。
- 从酒馆作者注记 / 扩展字段导入场景。
- 场景分组与批量启停。
- 生成后显示「本轮实际生效的场景」小标签。
