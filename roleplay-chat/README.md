# 幕间 · roleplay-chat

> 类酒馆（SillyTavern）的场景对话式 AI：自定义模型接入、角色扮演，并能在对话的任意位置插入「场景 / 导演指令」。

**状态：M1 + M3 场景核心 + M2 角色 / 人设 / 分支 / 角色卡导入导出已实现，可本地运行。** 已完成模型接入、角色、会话、流式对话、重新生成、分支切换、SQLite 持久化、AI 推荐、场景插入 / 上下文预览 / 时间线卡片、SillyTavern V2 角色卡（JSON / PNG）导入与 V2 JSON 导出、用户人设；世界书、头像、场景模板继续推进。
目录名保留 `roleplay-chat` 以便后续稳定引用，产品工作名暂定「幕间」。项目暂放在 `dsh-demo` 仓库的 `roleplay-chat/` 目录，确认后可拆分独立仓库。

## 本地运行

```bash
cd roleplay-chat
pnpm install
pnpm dev
# Web: http://127.0.0.1:5173
# API: http://127.0.0.1:8787
```

生产模式（单进程同时托管前端与 API）：

```bash
pnpm build
pnpm start
# http://127.0.0.1:8787
```

首次打开后，在「模型服务」里填一个 OpenAI 兼容端点（Base URL / API Key / 模型名）即可。数据保存在 `roleplay-chat/data/`（已 gitignore），API Key 使用本地主密钥加密；不要把 `data/` 提交到仓库。

质量检查：

```bash
pnpm typecheck
pnpm test
pnpm build
```

## 一句话说清

把「场景」变成一等公民：角色卡决定**谁在演**，场景指令决定**此刻在哪、发生什么、这一轮怎么演**——并且可以插在上下文里的任何位置、对话时间线的任何节点。

## 核心体验

1. **接入自己的模型**：OpenAI 兼容端点（DeepSeek、OpenRouter、各类中转站、Ollama、LM Studio、自建服务），填 Base URL / API Key / 模型名即可用。
2. **像酒馆一样角色扮演**：可导入 / 导出 SillyTavern V2 角色卡、用户人设（CRUD + 会话选择）、开场白 / 备选开场白、示例对话、分支切换；世界书（P1）。
3. **分段输入**：对话为主，场景 / 动作 / 神态按需展开，可预览组合结果，也可切回自由输入。
4. **AI 帮你想下一句**：根据当前剧情推荐 3 条你可以发送的内容，在输入框上方气泡里直接点 1 / 2 / 3 填入，不自动发送。
5. **场景随时插入（已实现）**：三种意图——「当前场景」「插入剧情」「这一轮要求」；底层支持时间线锚定、深度、系统常驻；一次性场景成功后自动停用。
6. **所见即所得（已实现）**：发送前可预览最终上下文，看到每条场景落在哪个位置、占多少 token。

## 技术栈（建议，待确认 D2）

- **前端**：React 18 + TypeScript + Vite + Ant Design 5 + Ant Design X + Zustand + TanStack Query
- **后端**：Node.js 22 + Fastify + TypeScript + Zod
- **存储**：SQLite（WAL）+ Node 内置 `node:sqlite`（M1；可平滑迁移 Drizzle）；头像、备份存本地文件
- **流式**：SSE（前端用 `fetch` + `ReadableStream`，因为生成请求是 POST）
- **测试**：Vitest + Playwright + 提示词装配快照测试
- **部署**：本地单进程，默认只监听 `127.0.0.1`；可选 Docker

## 术语

| 术语 | 含义 |
| --- | --- |
| 酒馆 / SillyTavern | 流行的开源 AI 角色扮演前端，本项目的对标产品 |
| 角色卡 | 角色的设定集合（描述、性格、场景、开场白、示例对话等），有 JSON / PNG 两种载体 |
| 人设 | 用户扮演的角色设定（姓名、身份、外貌、与角色的关系等） |
| 世界书 / Lorebook | 关键词触发的世界设定条目，命中后注入上下文 |
| 场景 / 导演指令 | 本项目的一等功能：一段舞台说明，可指定注入位置、身份和生效时长 |
| 深度（depth） | 注入点距对话末尾的距离，`0` 表示最后一条消息之后，`1` 表示之前，以此类推 |
| 分支 / swipe | 同一父消息下生成多个候选回复，可来回切换，形成对话树 |
| Prefill | 预填助手回复开头，引导模型续写（P1） |
